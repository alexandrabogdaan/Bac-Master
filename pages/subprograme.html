Subprograme

Noțiuni fundamentale despre declararea și utilizarea subprogramelor

Definiția subprogramului

Un subprogram este o bucată de cod (o colecție de instrucțiuni) separată de programul principal, care îndeplinește o sarcină specifică. În loc să scriem același cod de 10 ori, îl scriem o singură dată într-un subprogram și îl apelăm de câte ori avem nevoie.

Un subprogram se declară în C++ astfel:

tipulFunctiei numeleFunctiei(parametrii);

Exemple

  • Ex1: int suma(int a, int b);
  • Ex2: bool estePar(int n);

Parametri formali vs. Parametri efectivi

Ca funcția să își poată face treaba, adesea trebuie să îi trimitem date pe care să lucreze. Aceste date se numesc parametri.

Parametrii formali

Sunt variabilele "imaginare" declarate sus, în antetul funcției. Reprezintă doar niște reguli: "Când mă vei folosi, va trebui să îmi dai două numere întregi, pe care eu aici, în interiorul meu, le voi numi a și b".

Parametrii efectivi

Sunt datele reale, palpabile, pe care le trimitem efectiv din main atunci când apelăm funcția. Pot fi numere directe (ex: 5, 10) sau alte variabile (ex: x, y).

void adunare(int a, int b) // a și b sunt formali (doar țin locul)
{
    cout<<a+b<<"\n";
}

int main()
{
    int x=5, y=10;
    adunare(x,y); // x și y sunt efectivi (datele reale trimise)
    adunare(3,7); // 3 și 7 sunt tot efectivi
    return 0;
}

Cum transmitem datele? (Esențial pentru BAC)

Când apelăm o funcție din main, compilatorul trebuie să știe cum să trimită acele date reale (parametrii efectivi) către funcție. Sunt două modalități:

1. Transmiterea prin Valoare (Fără '&')

Când transmiți prin valoare, funcția primește o COPIE a variabilei tale originale.

Analogia cu rețeta: Ai o rețetă secretă de prăjituri scrisă pe o foaie (variabila din main). Un prieten îți cere rețeta (funcția o cere). Tu îi faci o FOTOCOPIE și i-o dai. Dacă el taie cantitatea de zahăr de pe foaia lui cu pixul, foaia ta originală de acasă rămâne absolut neatinsă!

Concluzie: Orice modificare face funcția asupra parametrului, se întâmplă DOAR pe copia ei. Variabila originală din main rămâne Neschimbată.

void incearcaSaModifici(int x) // x este doar o copie
{
    x=x+10; // Modificăm copia internă
}

int main()
{
    int numar=5;
    incearcaSaModifici(numar);
    cout<<numar; // VA AFIȘA TOT 5! Originalul nu a fost atins.
    return 0;
}

2. Transmiterea prin Referință (Cu '&')

Când pui un & (ampersand) în fața parametrului formal, funcția primește acces direct la ORIGINAL.

Analogia cu Google Docs: Tu și prietenul tău aveți un singur document partajat pe internet. Amândoi vă uitați la aceeași pagină. Dacă prietenul tău șterge un rând, rândul acela dispare instantaneu și de pe ecranul tău, pentru că lucrați pe același document.

Concluzie: Subprogramul lucrează direct cu spațiul de memorie din main. Orice modificare făcută în subprogram devine definitivă și vizibilă și în main. Folosim asta când vrem ca funcția să ne calculeze/modifice ceva și să ne returneze "rezultatul" salvându-l direct în variabila noastră.

void modificaDefinitiv(int &x) // & înseamnă acces la original!
{
    x=x+10; // Modificăm direct pe variabila din main
}

int main()
{
    int numar=5;
    modificaDefinitiv(numar);
    cout<<numar; // VA AFIȘA 15! Modificarea s-a păstrat.
    return 0;
}

Atenție la Capcană: Vectorii și Matricile

Regulă de aur pentru BAC: Tablourile (vectorii uni-dimensionali și matricile) se transmit ÎNTOTDEAUNA, AUTOMAT prin referință! Nu ai voie și nu trebuie să pui & în fața lor în antet.

De ce? Pentru că un vector este imens, iar compilatorul refuză să facă o copie la 1000 de elemente ca să nu blocheze memoria. Așa că trimite direct adresa originalului. Orice element modifici într-un vector într-un subprogram, rămâne modificat definitiv! 

// n este transmis prin valoare (doar copie)
// v este vector, deci este trimis AUTOMAT prin referință!
void dubleazaElemente(int v[],int n)
{
    int i;
    for (i=1; i<=n; i++)
    {
        v[i]=v[i]*2; // Se modifică direct vectorul original din main
    }
}

int main()
{
    int v[100]={0,1,2,3}, n=3;
    dubleazaElemente(v, n);
    cout<<v[1]; // Va afișa 2, elementul a fost modificat definitiv!
    return 0;
}

Prototipul și definirea funcției

O funcție trebuie și definită, nu doar declarată!

Atenție: eroare de compilare

În acest caz, vom avea o eroare de compilare, pentru că apelăm funcția înainte ca ea să existe vizual în cod:

#include <iostream>
using namespace std;

int main()
{
    suma(5, 10);
    return 0;
}

int suma(int a, int b)
{
    return a+b;
}

Cazul corect

Spunem programului de la început că există o funcție numită suma (aceasta e declararea), și o construim (definim) propriu-zis după "main".

#include <iostream>
using namespace std;

int suma(int a, int b); // Declararea (prototipul) funcției

int main()
{
    cout<<suma(5,10); // Acum va afișa 15
    return 0;
}

int suma(int a, int b) // Definirea funcției
{
    return a+b;
}
