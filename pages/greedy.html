Metoda Greedy

Teorie oficială + algoritmul general și problemele celebre de BAC

Definiția și Tipul Problemelor

Metoda Greedy („lacomă”) este o metodă parțială de optimizare utilizată în rezolvarea problemelor în care se dorește construirea unei soluții optime fără a fi necesară generarea tuturor posibilităților.

Modelul matematic: Se dă o mulțime $A$. Se determină o submulțime $B \subseteq A$ astfel încât să fie îndeplinite anumite condiții de optimizare specificate în enunț.
Pornim de la mulțimea vidă ($B = \emptyset$) și adăugăm în mod repetat în soluția $B$ elemente din $A$ până când scopul este atins.

Algoritmul General Greedy

Schema generală de pseudocod funcționează prin selectarea succesivă a celui mai bun element disponibil:

B ← ∅  // Submulțimea soluție este inițial vidă
terminat ← FALSE

Execută
    Alege convenabil x ∈ A  // Alegerea optimului local curent
    
    Dacă x poate fi adăugat în B Atunci
        B ← B ∪ {x}       // Elementul este păstrat definitiv
    Altfel
        terminat ← TRUE    // Se oprește selecția
    SfârșitDacă
Cât timp terminat=FALSE
Observație practică:
În C++, pasul de „alegere convenabilă” se realizează aproape întotdeauna prin sortarea prealabilă a elementelor din mulțimea $A$ după un criteriu bine stabilit (ex: crescător după timpul de finalizare, descrescător după eficiență).

Observații Critice și Caracteristici

Optimul Local

Adăugarea în submulțimea soluție se face alegând la fiecare pas cel mai bun element din acel moment. De aici derivă numele de Greedy (lacom).

Irevocabilitate

Odată ce un element a fost adăugat în soluția $B$, alegerea este definitivă. Algoritmul nu efectuează reveniri (backtracking) la pașii anteriori.

Corectitudine relativă

Alegerea optimului local nu garantează întotdeauna obținerea optimului global. Metoda este corectă doar dacă există o demonstrație că algoritmul nu pierde soluția optimă.

Eficiență computațională

Complexitatea este polinomială, de regulă $O(n \log n)$, fiind determinată de algoritmul de sortare inițial utilizat.

Cele două situații de utilizare

  • Cazul Certitudinii: Există o demonstrație matematică clară că algoritmul furnizează soluția optimă (cazul Problemei Spectacolelor).
  • Cazul Euristic (Soluție Acceptabilă): Problema admite doar rezolvări exponențiale de tip Backtracking ($O(2^n)$), iar o abordare Greedy oferă rapid o soluție suficient de bună în practică, deși nu neapărat optimă.

Probleme celebre la examenul de BAC

1. Problema Spectacolelor

Criteriu: Sortarea crescătoare a spectacolelor după ora de finalizare.

Raționament: Eliberarea sălii cât mai devreme oferă un interval maxim de timp pentru planificarea altor spectacole ulterioare.

struct Spectacol {
    int inc, sf;
};

Spectacol s[100];

bool cmp(Spectacol a, Spectacol b) {
    return a.sf<b.sf; // Sortare crescătoare după ora de finalizare
}

// În main():
sort(s+1, s+n+1, cmp);
int ult=0;
for(int i=1; i<=n; i++)
    if(s[i].inc>=ult) {
        cout<<s[i].inc<<" "<<s[i].sf<<"\n";
        ult=s[i].sf;
    }

2. Problema Continuă a Rucsacului

Criteriu: Sortarea obiectelor descrescător după eficiență ($\frac{\text{Valoare}}{\text{Greutate}}$).

Raționament: Obiectele putând fi fracționate, se încarcă mai întâi unitățile cele mai valoroase per kilogram pentru a maximiza câștigul total.

Atenție: Dacă obiectele nu pot fi tăiate (Rucsacul Discret 0/1), metoda Greedy NU mai garantează optimul global! Pentru varianta discretă se utilizează Programarea Dinamică.

Rezumat comparativ: Backtracking vs. Greedy

Criteriu Metoda Backtracking Metoda Greedy
Soluții returnate Toate soluțiile posibile ale problemei. O singură submulțime (soluție optimă).
Mecanism Încercare → Validare → Revenire (Backtrack). Sortare inițială → Alegere definitivă (Lacomă).
Timp de rulare Exponențial (Lent: $O(2^n)$ sau $O(n!)$) Polinomial (Rapid: de regulă $O(n \log n)$)
